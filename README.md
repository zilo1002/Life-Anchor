# Life Anchor · 活下去的理由

一个温暖、安静的单页数字港湾。

## GitHub Pages 部署

1. 将整个项目上传到 GitHub 仓库。
2. 进入仓库的 Settings → Pages。
3. Source 选择 GitHub Actions，或选择 Deploy from a branch。
4. 如果选择分支部署，选择 `main` / `root`。
5. 等待 GitHub Pages 构建完成后访问生成的网站地址。

本项目不需要 Node.js、npm 或构建工具，直接使用静态文件即可部署。

## 项目结构

```text
life-anchor/
├── index.html
├── css/
│   └── style.css
├── js/
│   └── app.js
├── data/
│   └── messages.js
└── README.md
```

## 文件职责

- `index.html`：页面结构与资源入口。
- `css/style.css`：主题、布局、响应式设计与动画。
- `js/app.js`：主题切换、声音、生命锚点按钮、消息卡片、粒子与交互逻辑。
- `data/messages.js`：内容库。后续增加/整理文案时可以只修改这里。

## 当前版本

这次重构以“最小变更”为原则：保留原页面的视觉设计、交互和内容逻辑，只把原来的单文件实现拆成适合 GitHub Pages 维护的静态项目结构，并移除了原 HTML 中重复注入的 iframe 高亮脚本/样式。

## 内容库

内容库现在分为两层：

- 原有内容：保留原项目已有文案。
- 原创扩展内容：新增 5000 条程序化组合的原创短句，不冒用真实人物、文学作品或心理学家的署名。

内容库统一由 `data/messages.js` 管理，后续可以继续把扩展层改造成真正的人工策展数据集，例如按「陪伴 / 存在 / 疲惫 / 孤独 / 重新开始」等主题维护，并加入内容 ID、标签、审核状态与来源字段。

## 后续完善建议

- 对原有引用逐条进行来源核验，避免误引、断章取义或网络伪引文。
- 将 5000 条扩展文案进一步人工策展，减少模板化语言的重复感。
- 内容增加 `id / category / tags / source / verified` 等结构化字段。
- 增加内容去重与相似度检测。
- 完善移动端交互、无障碍与键盘操作。
- 增加内容反馈机制，让用户可以标记「喜欢 / 不想再看到」。

## 语言

界面语言会跟随浏览器/系统的首选语言自动选择：

- 中文系统 → 中文界面
- 非中文系统 → 英文界面
- 不需要用户手动选择语言
- `data/i18n.js` 负责 UI 文案，内容库本身不强制翻译
